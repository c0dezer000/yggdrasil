## 2. Project Objectives

Build a simple, functional to-do application that allows a single user to:

- Create, read, update, and delete tasks (CRUD)
- Mark tasks as complete/incomplete
- Filter tasks by status (all, active, completed)
- Persist data (survive page reload)

---

## 3. Target Users

- **Primary:** A single user managing personal tasks
- **Future:** Multi-user with authentication (post-MVP scope)

---

## 4. Core Problems Being Solved

1. Task forgetfulness — a place to write things down
2. Task prioritisation — seeing what needs doing
3. Completion tracking — knowing what is done
4. Data persistence — tasks survive browser refresh

## 7. Recommended Technology Stack

| Layer | Recommendation | Justification |
|---|---|---|
| **Frontend** | Vanilla HTML/CSS/JS or React (lightweight) | MVP is small; vanilla keeps complexity low. React if growth expected. |
| **Backend** | None for MVP (localStorage) | No server needed at MVP. Add later if cloud sync needed. |
| **Database** | `localStorage` (MVP) / SQLite (future backend) | Zero-infrastructure persistence. |
| **Styling** | CSS custom properties + minimal framework (e.g. Pico CSS or Tailwind CDN) | Keep it clean without heavy tooling. |
| **Hosting** | GitHub Pages or Netlify (static deploy) | Free, simple. |
| **Package manager** | npm (if React chosen) | Industry standard. |

**Recommended default:** Vanilla HTML/CSS/JS with localStorage — zero build step, maximum simplicity.

## 14. Acceptance Criteria (Overall)

1. User can add a task by typing and clicking "Add" or pressing Enter.
2. User can mark a task complete by clicking its checkbox.
3. User can delete a task by clicking its delete button.
4. User can edit a task's text by clicking on it (inline edit).
5. User can filter tasks by All, Active, and Completed.
6. All tasks persist across page refresh (localStorage).
7. Empty input validation prevents blank tasks.
8. Interface is responsive and usable on mobile (320px+).
9. Empty state message shown when no tasks exist.
10. Task count shows remaining (incomplete) tasks.
