# Off-Map Protocol

For any request that does not map to a task in the active work unit.

**Classify aloud before acting.** Silent handling of off-map work creates work that no plan, log, or decision explains.

| Class | Definition | Handling |
|---|---|---|
| **(a) Misfit** | Belongs to an existing unit | Route it there. If that unit is Completed or Locked, this is a reopen proposal — stop and ask. |
| **(b) New scope** | Genuinely new work | Change request: problem, proposed change, affected canon, impact on completed units. Gardener approval, then a new unit. |
| **(c) Micro-task** | Trivial: under one loop, no schema, money, security, or external surface | Execute immediately, then record one line in the side-work log. Nothing exists outside the record. |
| **(d) Experiment** | Exploratory, uncertain outcome | Run in a branch or scratch location, explicitly outside canon. Afterwards: adopt via change request, or discard. Never merges silently. |

**Announce the classification**, e.g. *"This is off-map, class (b) — new scope. Drafting a change request before any work."*

Class (c) is the pressure valve: without it, small requests bypass the system and the bypass becomes habit. Class (d) protects the quality bar: exploration is legitimate, diluting canon with unvalidated experiments is not.
